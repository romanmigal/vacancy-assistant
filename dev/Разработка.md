# Помощник по вакансиям — для разработчиков

Внутренняя документация: устройство кода, тесты, сборка и релизы. Пользовательская — в [README](../README.md) и [docs/](../docs/); папка `dev/` в сборку и в «Помощь» программы не попадает.

![Архитектура для разработчиков](архитектура.svg)

```
razbor.py                 запуск из командной строки
vacancy_assistant/        вся логика; ею пользуются и окно, и командная строка
  app.py                  окно: сервер на 127.0.0.1, маршруты API
  web/                    страница окна: index.html, style.css, js/ — без сборки и зависимостей
  hh.py                   поиск на hh.ru: согласие на риск, паузы, предел 300 запросов в день
  sites.py                вакансии по ссылке, из сохранённой страницы и из текста
  rss.py                  ленты Хабр Карьеры и GeekJob: разбор, отбор по названию, раз в час, просмотрено.txt
  analysis.py             оценка, разбор, письма, резюме под вакансию, истории STAR и вопросы работодателю
  answer.py               разбор ответа модели по разделам — один для таблицы, карточки и окна «Мои оценки»
  mails.py                вакансии из писем hh (.eml): только номера из ссылок, без ключа входа
  company.py              «О компании» и окно «Компании»: агентство или работодатель, рейтинг hh, прошлые вакансии (компании.json)
  contacts.py             контакты и подбор референсеров
  profile.py              профиль и сборка промптов из шаблонов (шаблоны/, версии — в settings.py)
  model.py, cloud.py      запрос к модели: Ollama или GigaChat
  market.py               «Резюме против рынка»: слова и ❌-требования из вакансий с откликом и расхождений, ATS, прогресс,
                          подсказка «что прокачать» (рынок.json)
  gaps.py                 расхождения со своей оценкой с даты (модель «нет» / вы «да»), пересчёт после правки резюме и «Вернуть как было»
  dupes.py                склейка дублей: та же вакансия с другого сайта — ссылка к прежней карточке
  similar.py              «Хочу» выше у вакансий, похожих на свежие отклики: роль и TF-IDF по описаниям
  mask.py                 скрытие личных данных перед GigaChat: метки в запросе, обратно — в ответе
  summary.py              статусы, флаги, Сводка.md
  stats.py                раздел «Статистика»: метрики по периодам, воронка, скорость ответа
  salaries.py             окно «Зарплаты»: вилки, НДФЛ, курс ЦБ, группы, планка
  ratings.py, tune.py     свои оценки и автонастройка критериев
  calibration.py          калибровка: набор из своих недавних оценок (расхождения первыми), правки набора
  fix.py                  окно «Мои оценки» в карточке: своя оценка, правка критериев по одной вакансии
  criteria_history.py     версии критериев и образца письма
  funnel.py, artifacts.py этапы отклика; отправленные письма, резюме и файлы
  letter_templates.py     шаблоны сопроводительного письма
  backup.py               резервные копии и перенос профиля
  datadir.py              папка с данными: выбор и запоминание
  updates.py              проверка обновлений и «Что нового» для релиза
  help.py                 «Помощь»: README и docs/ страницей в браузере
  setup.py                мастер профиля, проверка компьютера
  network.py              доступ из домашней сети
  desktop.py, cli.py      запуск собранной программы; команды
packaging/                сборка установщиков: PyInstaller, .dmg, Inno Setup
tests/                    автотесты
```

- **Тесты:** `python3 -m unittest discover -s tests`. Модель и загрузка страниц подменяются, поэтому сеть и Ollama не нужны. В GitHub Actions тесты идут на Windows и Linux при каждой отправке.
- **Ответ модели** разбирает только `answer.py`: окно получает готовые разделы и оценки и само текст не разбирает. Новый вариант формата от модели — образец в `tests/fixtures/ответы/` и тест. Проверить разборы своих профилей: `python3 razbor.py check-analyses --all` (только чтение) — называет разборы без какой-то оценки, с пустым разделом или с оценкой, которая не совпадает с таблицей.
- **Установщики** собирает GitHub Actions: вкладка Actions → **build** → Run workflow, или тег `v*`. По тегу `v*` готовые установщики и `latest.json` публикуются релизом в публичном репозитории [job-search-assistant-releases](https://github.com/romanmigal/job-search-assistant-releases) — оттуда их скачивают пользователи, а программа узнаёт о новой версии. Для публикации нужен секрет `RELEASES_TOKEN` (токен с правом Contents: write на этот репозиторий); описание релиза — раздел версии из [docs/Что нового.md](../docs/Что%20нового.md) (если раздела нет — текст тега). **Перед релизом:** поднять `__version__` в `vacancy_assistant/__init__.py`, в «Что нового» заменить «(готовится)» датой — `## 0.5.0 — 30.10.2026`, — закоммитить и поставить тег `v0.5.0`. Mac-версию можно собрать и у себя: `pip install pyinstaller pypdf` и `bash packaging/build_mac.sh`.
- **Безопасность окна:** сервер отвечает только с этого компьютера и только той странице, которую сам открыл, — другие сайты в браузере не могут читать вакансии или менять статусы.
- **GigaChat:** ключ один на компьютер — `профили/облако.json` (в git не попадает); выбор модели — в `профиль.json` каждого профиля, и запросы задачи идут туда, что выбрано в её профиле. Сертификаты Минцифры для GigaChat лежат в `vacancy_assistant/certs/`.
